🔐 Federação Zero-Trust: GitHub Actions OIDC + OpenBao HA

Troca dinâmica de JWT efêmero por token de menor privilégio para leitura de segredos sem credenciais estáticas

Fase 1 Emissão do JWT

O GitHub Actions gera um token OIDC assinado contendo as claims do repositório, branch e commit via id-token: write.

Fase 2 Egress Proxy

O OpenBao, isolado na rede interna .maas, usa o tinyproxy no IAM para baixar as chaves públicas (JWKS) do GitHub.

Fase 3 Token Scoped

O OpenBao valida as claims e emite um client token temporário (TTL: 15m) vinculado estritamente à política iam-reader.

Fase 4 Leitura de Segredos

A automação faz consultas GET aos segredos em secret/data/iam/* e atualiza a stack do Keycloak e OpenFGA.
