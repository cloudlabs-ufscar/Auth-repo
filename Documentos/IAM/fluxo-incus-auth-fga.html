🛡️ Autenticação e Autorização no Incus (Cirrus & Stratus)

Comparativo técnico entre Device Code (CLI), Auth Code com PKCE (Web UI) e Autorização ReBAC via OpenFGA

CLI Flow Autenticação Incus CLI (Device Authorization Grant - RFC 8628)

Projetado para ambientes headless e sessões SSH sem capacidade de receber redirecionamento HTTP local. O terminal faz polling enquanto o usuário digita o código curto no navegador.

"Acesse https://cumulus.dc.ufscar.br:8443/realms/cloudlabs/device

Web UI Flow Autenticação Incus Web UI (Auth Code com PKCE - RFC 7636)

Projetado para navegadores completos. Utiliza redirecionamento nativo HTTP 302 protegido por PKCE (Proof Key for Code Exchange) para prevenir interceptação de código de autorização.

sequenceDiagram autonumber actor Dev as 👤 Usuário (Navegador) participant UI as 🖥️ Incus Web UI (Frontend) participant KC as 🛡️ Keycloak (IdP) participant INCUS as ⚙️ Incus API Backend Dev->>UI: Acessa https://cirrus.dc.ufscar.br:8443/ui/ UI->>UI: Gera code_verifier criptográfico e calcula code_challenge (SHA-256) UI-->>Dev: HTTP 302 Redirect para Keycloak rect rgb(22, 27, 34) Note over Dev,KC: Redirecionamento OIDC com PKCE Dev->>KC: GET /protocol/openid-connect/auth?
client_id=incus-cirrus&response_type=code
&code_challenge=XYZ&code_challenge_method=S256
&redirect_uri=https://cirrus.dc.ufscar.br:8443/ui/oidc/callback KC-->>Dev: Renderiza tela de login Dev->>KC: Autentica (GitHub ou Senha) KC-->>Dev: HTTP 302 Redirect para Incus Callback (?code=AUTH_CODE_123) end rect rgb(22, 27, 34) Note over UI,KC: Troca de Código por Tokens (Sem expor credenciais) Dev->>UI: GET /ui/oidc/callback?code=AUTH_CODE_123 UI->>KC: POST /protocol/openid-connect/token
(code=AUTH_CODE_123, code_verifier=SEGREDO_PKCE) KC->>KC: Valida se SHA256(code_verifier) == code_challenge original KC-->>UI: HTTP 200 {"access_token": "JWT...", "id_token": "..."} UI->>UI: Salva sessão no SessionStorage UI->>INCUS: GET /1.0 com Header "Authorization: Bearer JWT" INCUS-->>UI: Retorna dados do cluster e recursos permitidos UI-->>Dev: Exibe painel de controle do Incus end

Backchannel JWKS Obtenção e Cache de Chaves Públicas pelo Incus (Discovery)

O Incus consulta o Keycloak para baixar o conjunto de chaves públicas RSA (JWKS). As chaves ficam em cache na memória do Incus, permitindo validar assinaturas JWT de forma 100% offline e instantânea a cada comando.

Cache em Memória e Validação Offline do Token INCUS->>INCUS: Armazena chaves públicas em cache Note over INCUS: Ao receber requisições do usuário:
- Valida assinatura JWT usando a chave do cache (via cabeçalho 'kid')
- Valida expiração ('exp') e emissor ('iss')
- Extrai 'preferred_username' = "nicolas"
- NENHUMA chamada extra ao Keycloak é necessária!

ReBAC Authorization Consulta de Permissão do Incus ao OpenFGA (Check Request)

O daemon do Incus (PEP) delega a autorização ao OpenFGA (PDP) via chamada REST POST /check. O OpenFGA avalia o grafo Zanzibar no PostgreSQL e autoriza ou rejeita a operação.
